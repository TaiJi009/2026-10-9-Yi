# 2026-10-9-Yi · 变易

一个以《易经》六十四卦为主题的互动网页项目。目标形态：从太极生演到六十四卦，
起卦后展开本卦的「错综复杂」关系网（15 格变体系统），整个过程以抽卡式的动效呈现。

视觉约束：**仅黑白灰，靠明度多层次区分（tone ramp）**；交互形式：单文件 HTML，零依赖。

## 在线演示

https://taiji009.github.io/2026-10-9-Yi/

## 当前状态

`index.html` 已完成首版实现：单文件、约 1400 行，内联 CSS + 原生 JS，零依赖。
覆盖太极生演（屏 0–1）、逐爻起卦（屏 2）、成卦落定（屏 3）、15 卦关系网（屏 4），
起卦用大衍筮法的非均匀概率，视觉走黑白灰明度分层。

## 五屏流程

| 屏 | 内容 | 交互 |
|---|---|---|
| 0 静 | 太极呼吸 | **长按**太极（约 0.6s，有进度环）起卦 |
| 1 生演 | 太极 → 两仪 → 四象 → 八卦 → 六十四卦 | 仅首次自动完整播放，之后快速掠过；随时可 **跳过** |
| 2 起卦 | 六爻自下而上逐爻抽取（大衍筮法） | 每爻「蓄—落—显」三段节奏；可 **跳过**直接落定 |
| 3 成卦 | 本卦落定 + 光泽横扫；有动爻时并列 **之卦** | 点「展开错综 · 十五卦」进入第 4 屏 |
| 4 错综 | 本卦居中的十五卦关系网 | hover 任一邻卦，中心本卦里**对应变的爻**高亮；可切「分组视图」；可「重新起卦」 |

键盘：`Enter`/`Space` 长按等效，`Esc` 跳过。

## 第 4 屏：十五卦怎么排

位置本身承载语义：

```
                    综卦（倒转）
 变·上爻
 变·五爻                                   错卦（全反）
 变·四爻        ┌──────────┐               交卦（上下互换）
 变·三爻        │   本卦   │
 变·二爻        └──────────┘
 变·初爻

        互·去初  互·去上  互·去初上  互·去初二  互·去五上
```

- **左侧变卦阶梯**：卡片高度 = 所变爻位（初爻最低、上爻最高）→ 看一眼就知道变了哪一爻。
- hover 时，中心本卦按下表响应：

| 变体 | 高亮方式 |
|---|---|
| 变卦 | 亮起所变的那一爻 |
| 综卦 | 整卦旋转 180° |
| 错卦 | 六爻全亮 |
| 交卦 | 上三爻 / 下三爻分组框选并相向错身 |
| 互卦 | 被去除的爻变暗、保留下来的爻变亮，右侧叠两个括号标出「二三四 / 四五六」的重叠抽取 |

- **重合徽标**：回文卦（综=本卦）与八纯卦（交=本卦）会让某几格落到同一个卦上，
  该槽打「同本卦 / 同变·X爻」徽标，不留空、不覆盖。

## 规则实现

**数据模型**：爻 = 1 bit，六爻自下而上 `[初,二,三,四,五,上]`，阳=1。

```
三爻值(0..7)  = b0 + b1*2 + b2*4     坤0 震1 坎2 兑3 艮4 离5 巽6 乾7
重卦值(0..63) = 下卦(内) + 上卦(外)*8   乾为天=63  坤为地=0
```

14 个变体全部由纯函数算出（见 `RULES`）：

| 变体 | 实现 |
|---|---|
| 变卦 | 翻转第 i 位 |
| 综卦 | 数组倒序 |
| 错卦 | 逐位取反 |
| 交卦 | 交换低 3 位与高 3 位 |
| 互卦 ×5 | 按 `HU_MODES` 参数化下标抽取两个三爻子数组 |

**起卦概率**（大衍筮法，阳饶阴乏）：

| 爻 | 数 | 概率 |
|---|---|---|
| 老阴 × | 6 | 1/16 = 6.25% |
| 少阳 | 7 | 5/16 = 31.25% |
| 少阴 | 8 | 7/16 = 43.75% |
| 老阳 ○ | 9 | 3/16 = 18.75% |

老阴、老阳为**动爻**：视觉上取全程最亮的纯白 + 光晕 + 呼吸，并在爻右侧标 `○` / `×`。
有动爻时，第 3 屏会并列显示**之卦**（动爻全变之后得到的卦）。

## 自检

打开 `index.html?debug`，控制台会跑一遍规则断言（卦名表、15 格系统、
综/错/互的抽查、16 万次采样验证大衍概率）。

也可以在控制台直接用 `window.YI` 里的 `DATA / RULES / STORE / RENDER / ANIM / FSM / PLAYS` 调试：

```js
YI.RULES.bitsToName([1,1,1,1,1,1])           // "乾为天"
YI.RULES.buildVariants([1,0,1,0,1,0]).length // 15
```

## 代码结构

`index.html` 内部按 8 个命名空间分区，依赖严格单向：

```
DATA → RULES → STORE → RENDER → ANIM → FSM → EVENTS → BOOT
```

- `RULES` 绝不碰 DOM；`RENDER` 绝不写 state；`ANIM` 不认识业务语义，只认 `el` + keyframes。
- 动画主干用 WAAPI（`element.animate`）；全局动画注册表 + `epoch` token 负责取消——
  每次切屏 `cancelAll()`，所有在飞的 `await` 自动失效，这是跨屏串扰的解药。

## 视觉约定

全站仅黑白灰，靠明度阶梯承载语义：

| 层级 | 语义 |
|---|---|
| L0 近黑 | 虚空 / 太极未分 |
| L1 极暗 | 卦位槽、网格、未占用的爻位 |
| L2 暗 | 静爻（少阳 7 / 少阴 8） |
| L3 中 | 次要文字、标签、卦名 |
| L4 亮 | 落定的爻、正文 |
| **L5 近白** | **动爻**、焦点、高光 |

阳爻 = 两段各占 50% 的线 `scaleX(1)` 拼成实线；阴爻 = 两段 `scaleX(.88)`，中缝裂开。
翻爻只 morph `scaleX`，不换 DOM、不产生 reflow。

系统开启「减弱动态效果」时，所有时长乘以 0.15 并关掉抖动层——保留叙事，但不刺激。

## 开发环境

无构建、无依赖。直接用浏览器打开 `index.html` 即可，或起一个静态服务：

```bash
python3 -m http.server 8777
```

## 部署

推送到 `main` 分支时，GitHub Actions 自动把 `index.html` 发布到 GitHub Pages
（工作流：`.github/workflows/deploy.yml`）。该工作流**只发布 `index.html`**，
`docs/`、`README.md`、`.claude/` 都不会进入站点。

首次启用需一次性配置：仓库 **Settings → Pages → Source** 选 **GitHub Actions**
（不要选 "Deploy from a branch"，否则部署会以 `Get Pages site failed` 失败）。
也可在 **Actions** 页选「部署到 GitHub Pages」→ **Run workflow** 手动触发一次。
