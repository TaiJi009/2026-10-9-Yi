# 卜卦网站 Demo（单文件 HTML）— 实施计划

## Context（为什么做这个）

用户要做一个卜卦网站，最终形态是从太极生演到六十四卦、并能展开本卦的错综交互关系网。
本轮**只做 demo**：一个前端 HTML 文件，无框架、无构建、零依赖。

重点是**交互流程与动效**，要体现"生演抽卦"的过程（类似游戏抽卡/抽牌），而非视觉美观。
视觉约束：**仅黑白灰，靠明度多层次区分（tone ramp）**。

规则唯一真源：[六十四卦演变规则.md](六十四卦演变规则.md)——含生成逻辑、15 格变体系统、
互卦 5 种下标、八卦口诀。demo 的 DATA/RULES 依据它落地。

**已确认的四个取舍（用户拍板）：**
1. 起卦随机 = **大衍筮法**（非均匀：老阴6=1/16、少阳7=5/16、少阴8=7/16、老阳9=3/16）
2. 「生演」屏 = **仅首次进入自动完整播放，之后默认快速略过，全程可跳过**
3. 第4屏 15 卦 = **默认全铺（星座图），另提供「按 5 类分组」的视图切换**
4. 范围 = **只做屏 0–4**，不做卦辞/解卦

**核心设计判断（贯穿全程）：**
- 两条动效语言：**生成=垂直生长（裂分/累积）**，**变体=横向铺开（映射/连线）**。先竖后横。
- **爻线是唯一 UI 原子**：全站只用一种图形语言，明度分层天然落在爻线上。
- **"错综复杂"要被看见**：第4屏 hover 邻卦时本卦对应爻高亮，让变法规则本身可视化——这是 demo 的灵魂。
- **15 卦是算出来的，不是编出来的**：6-bit 数组 + 纯函数，可验证、可扩展。

---

## 交付物

**一个文件：`index.html`**（内联 CSS + 原生 JS，零依赖）。

单文件内按 8 个命名空间分区（IIFE），依赖严格单向：
`DATA → RULES → STORE → RENDER → ANIM → FSM → EVENTS → BOOT`
- `RULES` 绝不碰 DOM；`RENDER` 绝不写 state；`ANIM` 不认识业务语义，只认 `el` + keyframes。

> 若单文件超 ~1200 行难以维护，开发期可临时拆 `style.css` / `app.js`，交付前机械拼接回单文件（非构建步骤）。默认直接写单文件 + 分区横幅注释。

## 一、数据模型（6-bit 数组）

爻 = 1 bit，六爻自下而上：`bits = [b0初, b1二, b2三, b3四, b4五, b5上]`，阳=1。

```
三爻值(0..7): 坤0 震1 坎2 兑3 艮4 离5 巽6 乾7 = b0 + b1*2 + b2*4
重卦值(0..63): 下卦(内) + 上卦(外)*8
校验：乾=63 坤=0 泰=7 否=56
```

**变体对象的 meta（第4屏交互的命根子）**
```js
{ slot, kind:'ben|bian|zong|cuo|jiao|hu', label, bits, name,
  changedLines:[...],                       // 与本卦逐位 diff（变卦最可靠）
  hlMode:'lines|all|rotate|trigramSwap|removeKept',
  hu:{lower:[..],upper:[..],removed:[..]} } // 仅互卦
```

**互卦 5 种用参数化下标一次产出**（`HU_MODES`）：
| 变法 | removed | lower | upper |
|---|---|---|---|
| 去初爻 | [0] | [1,2,3] | [3,4,5] |
| 去上爻 | [5] | [0,1,2] | [2,3,4] |
| 去初上爻 | [0,5] | [1,2,3] | [2,3,4] |
| 去初二爻 | [0,1] | [2,3,4] | [3,4,5] |
| 去五上爻 | [4,5] | [0,1,2] | [1,2,3] |

## 二、动画机制选型

**主干用 WAAPI（`element.animate`）**，CSS animation 只做环境循环（太极呼吸、动爻脉冲），
rAF 只做测量/连续重绘（屏1 坐标、屏4 连线端点）。

理由：本 demo 的三诉求——**"蓄-落-显"精确节奏 + 逐爻错峰 + 中途取消/跳过**——正好命中 WAAPI 的
`{delay, easing, fill}` + `.finished` Promise + `.cancel()`，无需 ticker、无需监听 `animationend`、无需强制 reflow。

**节奏 token（数据化，写进 DATA）**
```js
EASE = { charge:'cubic-bezier(.5,0,.8,.2)',    // 蓄：慢入压住
         drop  :'cubic-bezier(.2,.9,.25,1.15)',// 落：快落微过冲
         settle:'cubic-bezier(.4,0,.2,1)' };   // 显：回稳
DUR  = { charge:520, drop:240, settle:220, flip:360, rotate:700 };
```

**取消的唯一解药：全局动画注册表 + epoch**
```js
let _anims=new Set(), _epoch=0;
reg(a){ _anims.add(a); a.finished.finally(()=>_anims.delete(a)); }
cancelAll(){ _epoch++; _anims.forEach(a=>a.cancel()); _anims.clear(); }
// 每个 await 后校验： if(my!==_epoch) return;  // 被 goto/skip 打断→静默退出
```
`FSM.goto()` 首行永远 `ANIM.cancelAll()`。`FSM.skip()` = cancelAll 后直接推到终态并 paint 一次。

`prefers-reduced-motion` 命中：`DUR.*` 全局 ×0.15、关抖动层（保留叙事，不直接关动画）。

## 三、爻线渲染

**每爻固定 3 层，阴阳不换 DOM，只改 CSS 变量**
```html
<div class="yao" data-yang="1" data-moving="0">
  <span class="seg seg-l"></span><span class="seg seg-r"></span><span class="mark"></span>
</div>
```
- 两段 `.seg` 各占 50%，`.seg-l{transform-origin:left}` `.seg-r{transform-origin:right}`。
- 阳爻：两段 `scaleX(1)` → 拼成实线。阴爻：`scaleX(0.94)` → 中缝裂开 6%。
- **翻爻** = 只 morph 两段的 `scaleX`，180ms 平滑"断/连"，无 DOM 交换、无 reflow。

**四种变法的 transform**
| 变法 | 数据 | 视觉 |
|---|---|---|
| 变卦 flipLine(i) | 翻转 bits[i] | 目标爻 `.seg` scaleX morph（前置 200ms 预亮） |
| 综卦 reverseBits | reverse() | `.yao-stack` 绕中心 `rotate(180deg)`，转完提交逆序并归零；**卦名 label 放 stack 外不转** |
| 错卦 invertAll | 逐位取反 | 6 爻 `delay:i*60ms` 依次 morph |
| 交卦 swapTrigrams | 低3↔高3 | 上下 `.trigram` 子容器相向 translateY 错身交换后归零 |

**明度分层（tone ramp）——不用颜色，只用明度极值编码"动爻"**
- 静爻（少阳7/少阴8）：中明度 `#8a8a8a`
- 本卦六爻落定：高明度 `#e8e8e8`
- **动爻（老阳9/老阴6）：纯 `#fff` + `drop-shadow` 光晕 + 1.6s 呼吸 + 右侧记号 `○`/`×`**
  → "哪一爻在动"由**唯一明度极值 + 唯一光晕 + 唯一记号**三重编码。
- 光晕用预模糊静态元素 + animate 其 opacity，**不逐帧 animate `filter`**（低端机掉帧）。

## 四、五屏流程

| 屏 | data-screen | 内容 | 动效基调 |
|---|---|---|---|
| 0 | `rest` | 太极呼吸，点击/长按开始 | 呼吸 |
| 1 | `generate` | 太极→两仪→四象→八卦→64 展开 | 生长/裂分（**仅首次自动，可跳过**） |
| 2 | `cast` | 六爻自下而上逐爻抽取，进度 1/6…6/6 | 蓄-落-显（抽卡节奏） |
| 3 | `settle` | 六爻组装落定，出卦名与本卦 | 落地 + 光泽 |
| 4 | `network` | 15 卦铺开，hover 高亮对应爻 | 映射/连线/翻转 |

**屏2 的一个 beat（抽一爻）三段：**
- 蓄 charge ~520ms（ease-in）：爻位高频抖动 `translateX ±2px` + 暗→亮扫描
- 落 drop ~240ms（回弹）：爻线从 `translateY(-40px) scale(.6) opacity:0` 落到位
- 显 settle ~220ms：亮度脉冲回稳；若 value∈{6,9}，脉冲不回零→转持续呼吸 + 最大明度

屏幕 beat 之间留 `per≈420ms` 思考间隙，形成"摇→停→摇→停"节奏。

**屏1 坐标全部公式预算**（绝不测量，避免 reflow 抖动）：
第 d 层第 k 个：`x=(k+0.5)/2^d * W`，`y=d*rowH`；固定 viewBox 后由 CSS 缩放；
64 节点用 `DocumentFragment` 一次性挂载。可选：第5层"8卦→64"绽放后收拢，避免长期铺满。

**屏2 与「之卦」联动**：抽到老阳/老阴（动爻）时，顺势演示"本卦→之卦"的变卦——这是变卦规则的高光时刻。

## 五、第4屏：15 卦关系网

**布局：固定 15 槽位 + 语义化位置（不做物理引擎/碰撞检测）**
- **本卦居中**（最亮）。
- **6 个变卦**贴中央本卦左右成竖直阶梯，**垂直高度 = 对应爻位高度** → "空间位置=变哪一爻"。
- **综卦**置正上/正下（"颠倒"），带 180° 小指示。
- **错卦**置最远端对角（"全反"=距离最远）。
- **交卦**置侧位（"上下互换"），配左右箭头。
- **5 个互卦**沿外围一段弧线排开，角标注明"去初/去上/去初上/去初二/去五上"。
- 用 CSS Grid 命名区域或 `absolute + left/top` 百分比钉死 15 槽；小屏降级 3 列滚动网格（连线和阶梯语义让位可读性）。

**默认全铺 + 提供「按 5 类分组」切换视图**（用户确认）。

**hover 反推变法 + 高亮对应爻**（中枢 = `ben.bits` 与 `variant.bits` 逐位 diff）：
```js
onHover(variant){
  switch(variant.hlMode){
    case 'lines':      setHot(centerHex, variant.changedLines, 'hot'); break;   // 变卦
    case 'all':        setHot(centerHex, [0..5], 'hot'); break;                 // 错卦
    case 'rotate':     tween(centerHex .yao-stack, rotate 0→180deg); break;     // 综卦
    case 'trigramSwap':setHot(centerHex,[0,1,2],'grpA'); setHot(centerHex,[3,4,5],'grpB'); break; // 交卦
    case 'removeKept': setHot(centerHex, variant.hu.removed,'dim');
                       setHot(centerHex,[...lower,...upper],'kept'); break;     // 互卦
  }
}
```
要点：变卦靠 diff 自动反推；综/错/交/互四类 **diff 无法还原语义**，必须依赖 meta 的 `hlMode`/`hu`。
互卦额外在中央卦右侧叠两个半透明括号 SVG 标记"二三四/四五六"的重叠抽取。

**SVG 连线层**：一层 `<svg class="net-links" preserveAspectRatio="none">` 覆盖网格、位于卡片下层；
本卦中心 → 14 锚点画微弯贝塞尔；入场用 `stroke-dasharray` 从 0 长到全。
重算时机：`ResizeObserver(grid)` + `resize`(debounce 120ms) + 入场动画 `.finished` 后 rAF；
坐标 `getBoundingClientRect` 减 svg rect 缓存到 Map，**不在 hover/mousemove 里重算**；
hover 只改对应一条 line 的类名。

## 六、起卦规则（RULES 唯一收口）

```js
LINE_PROB = { 6:1/16, 7:5/16, 8:7/16, 9:3/16 }   // 大衍筮法
isMoving(v) = (v===6 || v===9)                    // 动爻
```
开发期加 `console.assert`：16 万次采样，频率≈6.25/31.25/43.75/18.75%。

## 七、风险与规避

1. **动画状态竞争/跨屏串扰**（最高危）→ 单 epoch token，每个 await 后校验`my!==_epoch`即 return；`goto()` 首行 `cancelAll()`；所有 animate 经 `reg()`。
2. **快速重复点击/连点** → FSM 输入闸门 `if(busy)return` + `skip()` 为唯一合法打断；长按用 pointer 四件套（down/up/leave/cancel）；hover 用纯类名切换。
3. **屏1 生成树坐标/一次性插桩** → 坐标全公式预算、不测量；DocumentFragment 一次挂载；只 animate transform。
4. **对称卦重合（15 格≠15 卦）** → 保留 15 固定槽；若某变体 bits 与已放置者相同，该槽打"同本卦/同综卦"徽标 + 虚线连回（顺带把回文卦/纯卦知识讲出来），**不留空、不覆盖**。
5. **SVG 连线与布局不同步** → 只在入场动画 `.finished` 后 rAF 里 measure→compute→一次写入 `d`；ResizeObserver 兜底；hover 不重算。
6. **概率/动爻判定写错** → 收口在 RULES + 开发期采样断言。

## 八、文件内部顺序

```
<!doctype html><meta charset/viewport>
<style>
  /* TOKENS (tone ramp / EASE / DUR 的 CSS 镜像) */
  /* LAYOUT (screen 容器、15 槽 grid) */
  /* YAO (.yao .seg .mark，翻/转/移 keyframes 基类) */
  /* SCREEN 0..4 各屏样式 */
  /* @media (prefers-reduced-motion) */
</style>
<!-- 5 个 <section class="screen" data-screen="rest|generate|cast|settle|network"> -->
<!-- 屏4 内含 <svg class="net-links"> -->
<script>
  /* DATA */ /* RULES */ /* STORE */ /* RENDER */
  /* ANIM */ /* FSM */ /* EVENTS */ /* BOOT */
</script>
```

不用 `type="module"`、不用 CDN、不用 polyfill（目标现代 Chromium/Safari/Firefox）。

## 验证方式（端到端）

1. **本地打开** `index.html`（可 `open index.html`，或起一个静态 server）。
2. **规则正确性（控制台）**：
   - `RULES.bitsToName([1,1,1,1,1,1])` → 乾；`[0,...0]` → 坤；泰/否抽查。
   - 对任一卦 `RULES.buildVariants(bits)`，断言返回 **15 项**；手工核对某个卦的综/错/交/互是否与 MD 一致。
   - 大衍概率断言（16 万次采样）。
3. **流程走查**：屏0 长按 → 屏1 首次自动播放（再进可跳过）→ 屏2 六爻逐抽（含动爻演示之卦）→ 屏3 成卦 → 屏4 全铺，hover：变卦亮对应爻、综卦转 180°、错卦全亮、交卦分组亮、互卦暗去爻亮保留爻；再切"按类分组"视图。
4. **健壮性**：屏2 连点/快速跳过无残影错乱；`prefers-reduced-motion` 下动画缩短仍完整；缩放窗口连线跟随。
5. **响应式**：窄屏第4屏降级为 3 列网格可用。
