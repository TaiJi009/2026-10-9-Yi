# 卜卦网站 Demo 设计构想

> 本文是 demo 立项前的思考与认识，回答"为什么这么做"。
> 规则依据见 [六十四卦演变规则.md](六十四卦演变规则.md)；可执行的实施步骤见 [实施计划.md](实施计划.md)。

---

## 一、核心判断

**这个站有两条性质完全不同的轴线，不该用同一套动效语言。**

- **生成轴**（太极 → 两仪 → 四象 → 八卦 → 64）：这是**自上而下的分化**，一分为二、再加一倍。它的形态是"树 / 瀑布"，动效该是**生长、裂分、累积**——时间是向下的。
- **变体轴**（本卦 → 15 卦）：这是**横向的关联**，从一个点长出的邻域。它的形态是"星座图"，动效该是**映射、翻转、连线**——空间是铺开的。

所以整个站的动作隐喻是：**先垂直生长，再横向铺开**。这恰好吻合"从时间之流里抽出一卦，再展开它的关系网"的占卜体验。这条线定了，后面所有动效都有依据。

**第二个判断：爻线本身就是最好的 UI 原子。** 太极是圆的爻、八卦是三条爻、64 卦是六条爻、变体是爻在动（翻/倒/移/抽）。全站不需要第二种图形语言——把「爻」做成一个组件，视觉立刻统一，而且"黑白灰多层级"天然就落在爻线的明度上。

**第三个判断："错综复杂"要被*看见*，不是被*解释*。** 大多数卜卦站只给一个卦 + 卦辞；真正稀缺的价值在**关系网**。所以第 4 屏（变体网络）才是灵魂——hover 一个邻卦，本卦里对应变的爻就闪起来，用户"看见"了变法规则本身。demo 的交互力气应该压在这里，而不是压在有多个漂亮的开场。

---

## 二、视觉语言：明度分层 + 单一原子

要求是"黑白灰、明度多层次分明"。建议把它定义成一套**明度阶梯（tone ramp）**，让每一层承载一种语义，而不是随手取灰：

| 层级 | 明度 | 语义 |
|---|---|---|
| L0 | 近黑 | 虚空 / 太极未分（背景） |
| L1 | 极暗 | 卦位槽、网格、未占用的爻位 |
| L2 | 暗 | 静爻（少阴 8 / 少阳 7） |
| L3 | 中 | 次要文字、标签、卦名 |
| L4 | 亮 | 主动爻、正文 |
| L5 | 近白 | **动爻**（老阳 9 / 老阴 6）、焦点、高光 |

关键点：**动爻用最亮，静爻用中暗**。这样"哪一爻在动"不用文字说，一眼就分得出——这正好对接下一步"本卦之某卦"的变卦逻辑。

## 三、动效设计：抽卡的精髓是"节奏"，不是"华丽"

参考了 Balatro（小丑牌）的抽牌动效和 CSS 3D 翻牌，结论是：**抽卡感来自三个拍子的节奏，而不是彩带和爆炸。**

- **蓄**（起）：屏幕压暗、焦点收拢、轻微抖动 / 颗粒噪点 / "shuffle"——悬置。
- **落**（定）：爻线/卡牌飞入并**落定**，配一个极短的"嗒"。这是权重最重的一拍。
- **显**（亮）：一道光泽横扫过卦面——reveal。

易经的气质是"**静中生动**"，所以高光应该像**墨滴入水、爻线浮现**，而不是赌场式的爆彩。黑白灰恰好适合这种"克制的高光"——单一明度差就能做出高级感。

具体动效锚点：
1. **太极开天**：太极圆呼吸 → 一裂为二（⚊ ⚋）。
2. **加一倍**：两仪点往上逐层裂分 2→4→8，每根新爻"生长"出来，错峰出现（stagger）。这一步天然适合做**二叉树 / 瀑布**的形态。
3. **逐爻起卦**：六爻**自下而上**逐根抽，每根都有"摇—定"的小动画——这是 6 次微缩抽卡，合起来才是"抽到一卦"。
4. **成卦落定**：六爻齐了，整体一次更有分量的"落地"。
5. **变体星散**：15 卦从本卦**放射状散开**，每个派生卦由本卦某一个操作生成（翻/倒/移/抽），并且**可回溯高亮**是哪几爻在变。

## 四、交互流程（分屏草案）

| 屏 | 名 | 内容 | 动效基调 |
|---|---|---|---|
| 0 | 静 | 太极，极简，点击/长按开始 | 呼吸 |
| 1 | 生演 | 太极→两仪→四象→八卦→64 的展开 | 生长、裂分（可跳过） |
| 2 | 起卦 | 六爻逐爻抽取，进度 1/6…6/6 | 摇→定（抽卡拍子） |
| 3 | 成卦 | 六爻组装、落定，出卦名与本卦 | 落地 + 光泽 |
| 4 | 错综交互 | 15 卦网络铺开，hover 高亮对应变的爻 | 映射、连线、翻转 |
| 5 | （可选）解卦 | 卦辞/断语 | 静态 |

建议 demo **先做 0–4 屏，第 5 屏暂不做**——先把"形"和"动"做到位，卦辞是内容层，后面挂上去不难。

## 五、起卦的随机性

demo 里"抽卦"的随机分布，决定它像不像真的易经，可选择两种：

**大衍筮法（十八变，非均匀，"阳饶阴乏"）**

| 爻 | 数 | 概率 |
|---|---|---|
| 老阴 × | 6 | 1/16 = 6.25% |
| 少阳 、 | 7 | 5/16 = 31.25% |
| 少阴 、、 | 8 | 7/16 = 43.75% |
| 老阳 ○ | 9 | 3/16 = 18.75% |

**金钱卦（三枚铜钱，较均匀）**：老阴 1/8、少阳 3/8、少阴 3/8、老阳 1/8。

两者的"老阳 > 老阴"方向一致，但大衍更极端——这正是它的味道所在。**默认用大衍**，因为它一卦六爻里有 3/16 的动爻概率、且偏阳，抽出来的卦更"活"。

## 六、技术方案

**单文件、零依赖、数据驱动。**

- 一个 `index.html`：内联 CSS + 原生 JS，不用框架、不用构建。
- **爻 = 1 bit**。六爻就是一个 6 位数组（自下而上 `[初,二,三,四,五,上]`，阳=1）。那么：
  - **变卦** = 翻转第 i 位 → 6 个
  - **综卦** = 数组倒序（上下颠倒）
  - **错卦** = 逐位取反（XOR 63）
  - **交卦** = 交换低 3 位与高 3 位
  - **互卦** = 按下标抽取子数组再拼（去初爻 → `[1,2,3,3,4,5]`；去上爻 → `[0,1,2,2,3,4]`；去初上 → `[1,2,3,2,3,4]`；去初二 → `[2,3,4,3,4,5]`；去五上 → `[0,1,2,1,2,3]`）
- **64 卦只是一张"名字表"**（6 位 → 卦名），八卦是 3 位的子集。
- 渲染用 **DOM + CSS**（爻就是 div，翻/转/移全用 `transform`），只有第 4 屏的关系连线用一层 **SVG**。

这样做的好处：**15 卦系统是"算出来的"，不是"编出来的"**——可验证、可扩展，后面要挂 384 爻、卦辞、纳甲、先天方圆图，都是加数据不是改结构。

## 七、需要拍板的取舍

1. **起卦方式**：大衍（真实、六爻逐抽）还是金钱卦（快、均匀）？倾向大衍为默认。
2. **生演动画**：每次起卦都放一遍（可能烦）还是仅首次/可跳过？倾向首次自动 + 之后可跳过。
3. **动爻要不要出之卦**：抽到老阳/老阴时，是否顺带演示"本卦→之卦"？倾向要，这是变卦规则的高光时刻。
4. **第 4 屏的默认视图**：一屏同时铺 15 卦（信息密、有"星座"感），还是按类分标签（变卦/综/错/交/互）逐类展开（清楚但少了震撼）？倾向**默认全铺 + hover 高亮**，靠动效而非分页去解决密度问题。
5. **解卦/卦辞**：demo 阶段做不做？倾向先不做。

> 以上 5 点的最终决定见 [实施计划.md](实施计划.md) 的 Context 一节。

---

## 八、一句话总结

**先把"爻"这一颗原子做透，再用"垂直生长→横向铺开"两条动效语言串起生成与变体，把力气压在"看见错综关系"上；随机性用大衍的真实概率，实现上用 6-bit 数组把 15 卦全算出来。** 这样 demo 不只是"好看"，而是把 [六十四卦演变规则.md](六十四卦演变规则.md) 的规则**变成了可交互的证明**。
